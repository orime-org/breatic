# @breatic/shared — 包边界(MANDATORY)

> 项目级三层边界 + 进包判定题见根 [CLAUDE.md](../../CLAUDE.md#关键规范)。本文件只写本包的边界规矩,细节见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。

## 角色
**web + 后端共用**的纯协议层:zod schema · 类型 · 常量 · 跨服务事件契约的数据格式 · **统一 HTTP 传输层**(`http/`)与退避原语(`backoff.ts`)。

## 统一 HTTP 传输层(`src/http/`,#36 2026-07-30)
项目里**唯一**一处带重试的 HTTP 实现。**消费者按切片逐个接过来,接完之前旧的裸 `fetch` 调用点还在** —— 说「全项目都走它」要等最后一片(加守卫封住裸 fetch)落地才成立。判据在 `decide-retry.ts` 一处,分三层知识:**协议语义归传输层**(429/408 = 对方没处理 → 无条件重;其他 4xx = 请求本身的问题 → 永不重)· **应用语义由调用方声明**(`replaySafe`:再送一遍这个请求会不会产生第二次副作用 —— 只有调用方知道 `POST /predictions` 会多花一次 vendor 的钱)· **平台语义也归传输层**(`bodyReplayable`:流式请求体第一次就被消耗光了,物理上送不了第二遍 —— 这跟「有没有副作用」是两件事,拒绝原因也分开报)。**`replaySafe` 是事实陈述不是重试偏好**,别为「让它更可靠」到处开 true。重试次数(首次 + 2)与退避基数写死在 `http/constants.ts`、**故意不做配置**(原先 worker 和浏览器各配一份、已漂移成两种含义)。判定题:**我要加的重试参数,是「各场景天然不同」还是「统一一个答案更安全」?后者 → 写死,别开旋钮。**

**调用方给的函数只能描述请求,不能决定请求**:传输层只收一个调用方函数 —— 确定性失败判据 `isFatal`(比如 agent 的 SSRF 守卫拒了某个地址,重发一万次也是同样结果)。它抛错时一律回退到「它没回答」,而不是让它顶替真正的失败。判定题:**这个函数是调用方给的吗?是 → 它抛错时我该怎么继续,而不是跟着一起死。**

**等待多久由对方定,上限只用来判断等不等(user 2026-08-01 拍板)**:对方在 `Retry-After` 里报了时间,要么**照它说的等**,要么**根本不等、直接失败并把这个数交回上层**;中间那个「截断成我们自己的数」是错的 —— 它等于假装遵守了一个谁都没同意的约定。上限只做这一个判断:调用方声明 `interactive` 就用 10 秒(有人在屏幕前等)、不声明就用 60 秒。**对方没说话时才轮到我们自己估**(指数退避,唯一允许编数字的地方);报了一个已经过去的时间 = 没有可用指令,同样回到自己估。判定题:**这个等待秒数是对方给的还是我编的?对方给的 → 要么照办要么终止,不许改数字。**

**读 body 完全不归传输层管(user 2026-08-02 拍板)**:读多久、读多大、怎么中断,全是应用层的事。**底层协议本来就处理了超时,在上面再叠一层是重复的** —— 实测:Node 自带的 fetch 碰上「发完响应头就装死」的服务器,**301 秒后自己拒绝**(`UND_ERR_BODY_TIMEOUT`)。曾经有过一版 604 行的响应体守卫做这件事,已整体删除:它做的正是底层已经在做的,而且它是**唯一**逼着传输层去监听取消信号的东西 —— 监听就得持有对象,那才是当时那个泄漏的根。判定题:**我正要在传输层里管 body 的什么事吗?停 —— 那不是它的事。**

**交出去的就是原生 `Response`,交完撒手、什么都不持有**:不包装、不代理、没有句柄。**没人持有的对象本来就会被回收,所以不需要任何「强制释放」的约定** —— 曾经那版包了一层句柄,为了能中途取消就得在调用方的停止开关上挂一根线,而那根线拴着整个响应:实测 200 个没读的响应留 200 个监听器,裸 `fetch` 留 1 个,**现在也是 1 个**。一个连带后果要知道:传输层在每次尝试结束时就从调用方的信号上摘掉了,所以**响应交出去之后,调用方再触发停止不会中断正在进行的读取** —— 要中断读取用 `response.body?.cancel()`,那本来就是拿到任何 `fetch` 响应后该用的方式。判定题:**我正要在传输层里记住刚交出去的东西吗?停 —— 交出去就不是它的了。**

**它自己不写日志(library 边界),但发生了什么一样交给上层 —— 换成随结果返回**:每次调用返回 `HttpOutcome`,带着投递了几次(`attempts`)、为什么停(`stopped`)、服务器要求等多久(`retryAfterMs`),应用层拿到这些自己决定记不记、怎么记。**这不是「不报告」,是把报告从回调换成了返回值** —— 回调要在整个调用期间被持有、还要防它抛错顶替真正的失败,而返回的数据两样都不需要。判定题:**我这个调用方把返回的 outcome 用上了吗?整个丢掉 → 这条路上的重试对运维完全不可见。**

## 进本包判定题
web **用得到**吗?用得到 → `shared`;用不到 → `core`。

## 可 import 谁
- ✅ 外部 npm(必须**浏览器安全**:零 `node:*` / `fs` / `async_hooks`,`sideEffects: false`)
- ❌ `@breatic/core` / `@server` / `@worker` / `@collab` / `@web` —— 一个都不行(shared 是最底层)
- 本包内部用 `@shared/*` 前缀

## 暴露啥
**单入口** `src/index.ts`(`tsup` 全 bundle),不开多 subpath 入口(多入口会把 `@shared/*` 泄漏进 dist)。

## 怎么拿配置
不拿。shared 是纯数据/类型层,不读配置、不读 `process.env`、不写日志。

## 守卫
`breatic/no-relative-import`(走别名)· repo-lint 的 `no-unresolved-alias-in-dist`(dist 不漏别名)· `breatic/no-library-env-access`(零 `process.env`)· `breatic/no-library-logger`(零 logger)。
