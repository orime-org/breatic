# @collab — 包边界(MANDATORY)

> 项目级三层边界 + 进包判定题见根 [CLAUDE.md](../../CLAUDE.md#关键规范)。本文件只写本包的边界规矩,细节见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。

## 角色
**Hocuspocus 独立进程**:Yjs 文档同步 + PG 持久化 + Redis 跨实例 + 消费 Redis Streams 写 canvas 节点。只它认识 Hocuspocus。

## 分层(包内,目录即分层)
- `hooks/`(`auth` / `meta-write-attempt-log` / `presence` / `awareness-identity` / `presence-wiring` / `unload-gate`〔文档离开内存前最后一道:有未存内容就补传一次,不成就把内容写进救援文件 + 记日志 + 通知运维,然后放行。**永不抛异常** —— 抛了会让库中止卸载,把 0 连接的文档永久卡在内存里〕)= Hocuspocus 生命周期钩子,协作事件适配,翻译 Yjs 事件 ↔ 持久化/流。**meta 文档的写入边界靠连接级只读**(`auth.ts` 对 meta 无条件 `readOnly`,框架在每个写入口自己拒),`meta-write-attempt-log` **只记日志不拦截** —— 早先那道在这里判「拒不拒」的守卫要精确列举框架内部消息类型才能认出一次写入,漏一种就静默放行,已删
- **协作身份由连接权威确定,浏览器一个字都不自报(MANDATORY,#1886)**:服务端在 `onAuthenticate` 就从凭证解出了这条连接是谁,**那个 id 是唯一真相源**。① **在场名单**(meta 文档的 `users`,只存 `id` / `online` / `lastSeenAt`,**没有名字头像** —— 那些各端自己从项目成员名册拉)只有服务端写,经 `presence.ts` 的纯规则 + `presence-wiring.ts` 接进 `connected` 和 `onAwarenessUpdate`。**「在线」只被断言、「不在线」只被推断**:socket 关闭时**什么都不写**(一条 socket 结束不等于主人走了,多实例下别的连接在这台机器看不见),清扫把「没人在刷新」的记录关掉,而清扫搭在**心跳**上、不搭在文档载入上(载入那一刻记录最新、且只要有人在文档就永不卸载,搭在那儿等于永远扫不到)。心跳能把已离线的记录**写回在线**(错误复活下一轮自愈,错误离线是永久的)。**meta 文档的 awareness 通道上只有心跳,不传光标 —— 谁往 meta 的 awareness 上发光标都是 bug**(光标只在 canvas / document 这类空间文档上);所以每个心跳都写、不做任何限流,两次写之间的最大间隔 = 浏览器的心跳间隔。判定题:**这一帧是发给 meta 文档的 awareness 吗?是 → 它只可能是心跳**(meta 的 socket 上还跑着 space / tab 的 stateless RPC,那走另一个钩子、跟在场状态无关)。门槛一个数(`presence_stale_after_ms`,90 秒)在 `config/collab.yaml`,必须大于最慢的心跳间隔(后台标签页 60 秒),有测试钉住;② **光标身份**经 `beforeHandleAwareness` 由 `awareness-identity.ts` **逐条**盖章 —— 一个入站帧里既有发送方自己的状态、也有它转发的别人的状态(上游库的疏忽,见 #1887),按 Yjs client id 判归属:自己的或还没登记的盖,登记在别人名下的原样放行。**服务端整个 `user` 字段说了算,只保留客户端的窗口焦点标志**(只有浏览器知道)。判定题:**这个身份是从连接的凭证来的,还是浏览器说的?浏览器说的 → 不作数**。**这条只有 `presence-wiring.ts` 读钩子载荷** —— 提取逻辑写两份的守卫,会出现测试全绿而生产什么都没做的情况(被替换掉的那道守卫正是如此)
- `services/`(`persistence`〔含懒种子 fetchDoc 兜底;**#40 起不再用现成的 extension-database**,自己写,因为「谁可以写库」这个决定要有地方放 —— 库每次编辑后都会触发存盘且没有开关能关,而现成扩展在调我们的写库函数**之前**就把整份文档编码好了。没有 arm 就立即返回、一个字节都不编码〕 / `store-tracker`〔每份文档「有没有未存下的内容」+ 一次性 arm。**数改动次数,不用 Yjs 状态向量** —— 向量看不见删除(删除进 delete set、不推进时钟),实测会丢删除〕 / `store-loop`〔定时存盘,唯一的重试机制:库不重试,空闲文档也没有新编辑能捎带重试〕 / `store-alert`〔存盘彻底失败时通知运维,按文档去重〕 / `rescue-file`〔最后一份拷贝写本地磁盘,永不自动清理〕 / `yjs-documents.repo`〔yjs 库唯一 repo〕 / `lazy-seed` / `lifecycle-listener`〔删除/复制命令消费者〕 / `event-stream` / `space-rpc` / `task-listener` / `members-sync` / `space-delete-lock`〔DB3 fencing 锁〕 / `connection-registry`〔#1421 跨实例连接数 sorted set〕 / `connection-tracking`〔连接数上限 tracking 策略:meta 豁免的 `shouldTrackConnection` 守卫〕 / `handling-sweeper`〔#1569 handling 租约清扫:afterLoadDocument + 5min 周期扫,超 1h/无 handlingBy 的 handling 节点打回 idle,直接 doc 引用不走 openDirectConnection;命名 origin 只给读日志的人指名写者,**不是清扫不进用户撤销栈的原因**(origin 不过网线,前端撤销跟的是只含本地 Symbol 的白名单)〕)= collab **自带的协作业务**(本质是协作适配,跟 Hocuspocus 绑死,留本包)
- `infra/`(`health-checks` / `connection-gate`〔连接准入:`onUpgrade` 从原始对端地址裁决身份,回环豁免、非回环取 nginx 设的 `x-real-ip` 否则 403 拒绝;裁决本身写进请求头传给 `onConnect`,不让下游拿身份字符串重推〕 / `client-identity`〔上面那条规则的纯判定,不碰 I/O〕 / `socket-ceilings`〔库里几个「超了就关掉整条 socket」的上限,从 `max_documents_per_socket` 一处推导〕)= 本包支撑设施(对齐 core/server 的 `infra/`)
- 根:`index.ts` = composition root(启动 `initCore(process.env)`,唯一读 `process.env` 处;`config.ts` 等经 core 的 `env` proxy 读注入后的配置)· `hocuspocus.ts` = Hocuspocus 装配(把 hooks + services 接进 Server)· `bootstrap-config.ts` / `config.ts` = 引导 + 配置

## 可 import 谁
- ✅ `@breatic/core` 的**基础设施**(`getRedis` / `getStreamRedis` / `getCollabRedis` / `createRedisClient` / `pingDb` / `pingRedis` / `checkInfraReady` / `taskEventsStreamKey` / `startHealthServer` / `initCore` / `MONOREPO_ROOT`,以及 `Redis` 类型)+ `@breatic/shared` + 外部 npm
- ❌ `@server` / `@worker` / `@breatic/domain` —— 服务之间互不 import;**collab 绝不依赖 domain**(server+worker-only 的 AIGC 业务,`lint:dependency-cruiser` 的 `collab-no-domain-import` 规则强制)
- ⚠️ **但 collab ≠ 只用 core infra**:鉴权 / 会话 / 成员事件这类**全后端(含 collab)必须一致**的逻辑属 core 共享内核,collab 用 core 的统一鉴权。**鉴权已统一(二次调整 PR2)**:`hooks/auth.ts` 调 core 的 `getSession` + `projectAuthService.loadProjectRole`,跟 server 共用同一套原语,不再手写 `redis.get(:session:)` / 裸 SQL `loadProjectRole`。旧表述「collab 只借 core infra、业务不引入」**已作废**(它把鉴权漂移当成了设计)
- 🗄️ **DB 适配(2026-06-03 两 PG 库切换后)**:collab **不碰 postgres.js 驱动、不手搓连接池**,但**是 yjs 库的唯一运行时用户**——`yjs_documents` 查询 repo 已从 core 搬到本包 `services/yjs-documents.repo.ts`(一表一 repo,家搬了),经 core 的 **`yjsDb` 单例**(`YJS_DATABASE_URL`,独立 PG 库)跑 Drizzle 查询;驱动/池/表结构(`yjs-schema.ts`)/迁移仍只在 core。本包持久化(`persistence`,含懒种子)/ 空间存在性读(`auth`)/ space-rpc 软删·恢复 / 生命周期消费者(`lifecycle-listener`)全走这个本地 repo。`postgres` 驱动包仍不在本包 deps,但**新增 `drizzle-orm`**(同 core 版本)跑查询。健康探针 `pingDb()`(双库都探),boot 连通性检查走 core `checkInfraReady`(双库)。CI 强制:`breatic/no-postgres-outside-core`(驱动只许 core)+ `breatic/no-yjs-documents-outside-repo`(allowlist 指向本包 repo + core `yjs-schema.ts`)+ `breatic/no-raw-sql-outside-repo`(本包裸 SQL 只在 `*.repo.ts`)
- 🔴 **Redis 适配统一(2026-06-02)**:collab **不直接依赖 ioredis 驱动**。`Redis` 类型从 core re-export 拿(`import type { Redis } from "@breatic/core"`);会话查的 Redis 改用进程 `getRedis()` 单例(DB0,同 server/worker);**订阅 / 阻塞流 / Hocuspocus pub-sub 等专用连接**仍经 core 的 `createRedisClient` 工厂建——Redis 协议要求每个角色独占 socket,**连接数收不了**(跟 postgres 单池多路复用本质不同)。**Redis 拆 4 连接(2026-07-01):Hocuspocus 跨实例 pub-sub 连接 + `space:delete` 分布式锁 + 每文档连接数 registry 都走 `getCollabRedis()`(DB3 `REDIS_COLLAB_URL`,collab 实例间协调库,与跨服务 Streams DB2 分开,以后可整体拆独立 Redis 实例)。删除守卫 = fencing 锁(唯一 token + Lua check-and-del,TTL 兜底)串行化 + 锁内读 PG 权威 space 数(`countLiveSpaceDocs`),防多实例并发删除把 space 删到 0。连接数 registry(`services/connection-registry.ts`,#1421)= 每文档一个 sorted set(member `{instanceId}:{socketId}`,score 心跳戳),让 `max_connections_per_document` 上限跨实例计数(本地 `getConnectionsCount()` 只数本实例);登记绑 `connected` 钩子、注销绑 `onDisconnect`(经 `services/connection-tracking.ts` 的 `shouldTrackConnection` 守卫,meta 豁免),两头绑同一 Connection 生命周期防幽灵泄漏;心跳续期 + TTL 崩溃自愈 + fail-open。细节见 DD 2026-07-01**。stream key `:stream:task-events` 从 core 的 `taskEventsStreamKey()` 拿(跟 worker 发布同源,消灭两处各造的静默断风险);健康探针走 `pingRedis()`。`ioredis` 包已从本包 `dependencies` 移除。CI 强制:`breatic/no-ioredis-outside-core`(驱动只许 core)
- 本包内部用 `@collab/*` 前缀

## 怎么拿配置
入口注入后经 core 读;collab 配置走 `config.ts`。本包逻辑不直接读 `process.env`。

## 关键路径
Yjs 协作 = 关键路径,必 100% TDD;hook 顺序坑(`onConnect` 在 `onAuthenticate` 前 fire,`context.user` 未就绪)等已知陷阱见 [docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md)。改 collab 源码(或依赖 `core/dist` 重建)tsx watch 自动重启拾取,不需手动 kill;优雅关闭先关 WS 监听端口 + 整体超时兜底(`runGracefulShutdown`),重启不撞 EADDRINUSE。
